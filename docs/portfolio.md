## Project description (about 80 words)

Built RecyTrack, a full-stack data reliability platform that ingests recycling-operation records from CSV files and a
simulated API, validates and standardizes material events, quarantines suspect data with traceable reasons, and
reconciles material quantities using PostgreSQL, FastAPI and React. On a 225-row labeled synthetic test set, the
validation rules detected all 33 faulty rows with 0 false positives on 192 clean rows; repeat imports created no
new events for rows with a source ID, and all 7 reconciliation scenarios matched their expected results.

## Resume bullets

- Built a FastAPI + PostgreSQL ingestion pipeline that stores every raw row unchanged and applies documented
  validation rules (VAL-001…VAL-009 per row); on a 225-row labeled synthetic test set it detected 33 / 33 faulty rows with 0 false positives
  on 192 clean rows (rules and labels written by me, so this shows designed behavior, not real-world accuracy).
- Made imports idempotent with a payload-hash check plus a database unique constraint: re-importing each labeled set
  created 0 new events for keyed rows (10 / 10, 14 / 14 and 200 / 200 keyed rows detected as duplicates).
- Implemented a `Decimal` material-flow reconciliation with configurable tolerance that returns `NEEDS_DATA` instead
  of guessing when stock counts are missing; all 7 labeled scenarios match their expected status, variance and
  tolerance.
- Added a measurement script run in CI as a regression guard, 227 backend and 61 frontend automated tests, a React
  dashboard, and bounded retries for a simulated API source; a 10,000-row synthetic CSV imported in 6.58 s on SQLite
  on a Windows 11 development machine (target < 30 s).
